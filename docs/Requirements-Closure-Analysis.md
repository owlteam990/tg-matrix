# 需求闭环分析

- 依据文档：`docs/Telegram-Solutions-Feature-List.md`
- 整理日期：2026-10-08
- 文档版本：1.2
- 用途：区分「已闭环 / 部分闭环（可做）」与「未闭环（明确不做）」的需求，作为后续 MVP PRD 与排期输入。
- 产品方向补充：自研工具需支持 **Windows + macOS**（竞品原文仅强调 Windows）。
- 技术栈倾向（已定）：**Tauri 2 + Vue 3 + TypeScript + Go/gotd sidecar + SQLite**。

> 判定标准：  
> **已闭环** = 业务目标清晰 + 接口/实现路径可推断 + 成功/失败边界可写验收标准（即使效果有平台限制）。  
> **部分闭环** = 目标大致清楚，需补规格后可做。  
> **未闭环** = 业务语义不明或依赖未公开 → **本产品明确不做，不进入排期。**

---

## 0. 总览结论

| 维度 | 结论 |
|---|---|
| 竞品功能盘点 | 基本完整（25 模块 + 平台能力） |
| 自研候选功能 | 新增 7 项业务候选（C01-C07）及 1 项平台候选；仅标优先级，尚未批准进入 MVP |
| 自研范围 | **仅做已闭环 + 部分闭环**；未闭环功能 **永久移出范围**（除非日后单独立项重新闭环） |
| 功能层统计 | **16** 已闭环可做；**7** 业务项部分闭环可做（补规格后）；**2** 业务项未闭环 **不做**；另有竞品提及但未确认的扩展能力 **不做** |
| 平台共用能力 | 清单有，但任务状态机、错误模型、存储与授权规格需补文 |
| 产品层（非竞品） | MVP 切分、双端验收、许可证、安全存储等尚未成文（属实现规格，不是业务功能砍掉） |

**一句话：** 原 25 项中，仅已闭环与部分闭环项属于当前可做范围；新增候选项需先经产品评审，优先级不等于开发承诺。

## 1. 已闭环需求（做）

下列项可在补齐统一任务/错误模型后进入详细设计与实现。

### 1.1 业务功能

| 编号 | 功能 | 闭环依据 | 验收要点（可写进用例） |
|---|---|---|---|
| F01 | 按用户名发送私信 | 目标解析 → `messages.sendMessage` 路径清晰 | 合法用户名可发送；隐私/拉黑/停用有明确错误分类；日志区分接口成功与业务结果 |
| F02 | 按手机号发送私信 | `contacts.resolvePhone` / 导入联系人路径清晰 | 结果区分：匹配、未匹配、隐私限制、失败、待重试；禁止把「未匹配」一律判未注册 |
| F06 | 批量加入群或频道 | 公开加入 / 邀请链接接口明确 | 成功、需审批、已在群、链接失效、加入上限分别记录 |
| F07 | 批量退出群或频道 | 遍历会话退出路径明确 | 退出成功/失败可追溯；不宣称清除服务器历史 |
| F08 | 将联系人加入群 | 联系人实体 + 邀请接口明确 | 无邀请权、对方隐私拒绝、非双向联系人有错误提示 |
| F09 | 按用户名添加成员 | 解析用户 + 邀请 + 任务分配可设计 | 群与频道规则差异需在 UI/日志标明；隐私拒绝可复现 |
| F11 | 账号检查 | 授权校验 + 拉取自身资料即可 | 输出可用/失效/冻结等状态；明确「检查通过 ≠ 所有操作可用」 |
| F12 | SpamBot 状态检查 | 与官方机器人对话并解析 | 多语言解析策略可定义；无回复/超时可定义 |
| F14 | 举报工具 | 客户端举报接口可封装 | 仅验收「提交成功/失败」；不验收「是否处罚」 |
| F15 | 频道所有权转移 | `channels.editCreator` + 2FA 流程明确 | 非所有者、2FA 错误、冷却等待可复现 |
| F16 | 用户名占用 | 创建频道 + check/set username 明确 | 可用/已占用/保留名/额度不足可区分；不承诺必得名 |
| F19 | 添加联系人 | `importContacts` / `addContact` 明确 | 导入结果字段完整；不暗示获得隐藏号码或双向关系 |
| F20 | 删除联系人 | 读取并删除联系人明确 | 删除后列表一致；不宣称清除聊天或风控历史 |
| F21 | 清理全部私聊 | `messages.deleteHistory` 路径明确 | 范围确认、部分失败、双方删除选项可验收 |
| F23 | 成员采集 | `channels.getParticipants` / 从消息整理发言者 | **必须标注数据来源**（成员列表 vs 发言者）；隐藏成员不保证完整 |
| F25 | 手机号检查 | 与 F02 同源能力，输出可结构化 | 五态结果：匹配 / 未匹配 / 限制 / 失败 / 待重试 |

### 1.2 平台共用能力（做）

| 能力 | 闭环依据 | 仍需在实现规格中写死的细节 |
|---|---|---|
| 会话导入（Session + JSON） | 竞品与 gotd session 存储均可落地 | 重复导入、失效文件、格式错误提示文案 |
| 账号列表 | 本地库 + 状态刷新即可 | 状态字段枚举、筛选规则 |
| 代理分配 | 每账号独立代理为常规做法 | 故障时暂停策略、连接状态展示 |
| 执行节奏 | 间隔/并发/单账号上限为本地配置 | 配置上限 ≠ 官方额度（文案必须写清） |
| 实时日志 | 进度/数量/错误可本地落库 | 接口成功 vs 业务结果分层 |
| 数据导出 | CSV/表格导出路径明确 | 字段字典、编码、去重、附件完整性 |
| 本地存储 | SQLite + 加密目录可设计 | 密钥管理、备份、迁移路径 |

## 2. 部分闭环需求（补规格后做）

业务目标大致清楚，需补规格后排期（可进二期），**仍在产品范围内**。

| 编号 | 功能 | 已清楚部分 | 待补规格 | 建议 |
|---|---|---|---|---|
| F03 | 按用户 ID 发送私信 | 需要 `user_id + access_hash`；按账号缓存实体 | 仅数字 ID 时的降级策略；跨账号禁止复用的强制校验与提示 | 补「实体缓存隔离」规格后可做 |
| F04 | 群组定时发布 | 发送/转发 + 调度组合明确 | 错过时刻策略、去重、中断恢复、重复发布定义 | 先定义任务状态机再做 |
| F10 | 账号养号 | 可执行阅读/在线等协议活动 | 活动清单、节奏；**不能承诺免限制** | 二期；验收只验「动作执行」，不验「养号效果」 |
| F13 | 用户行为模拟 | 与 F10 类似，协议层可模拟部分行为 | 是否仅协议层；不验收「像真人」 | 与 F10 合并设计或降级 |
| F18 | Session 转 TDATA | 转换语义清楚（不改变服务器状态） | 源格式兼容矩阵、双向转换范围、失败场景 | 二期专项；MVP 只做 Session 导入 |
| F22 | 多账号统一私信中心 | 映射概念清楚：内部汇总 → 原账号 → 原用户 → 原消息 | 串号防护、附件、回复引用、编辑删除同步、断线恢复、去重 | 二期；需单独 PRD |
| F24 | 群内容采集 | 分页历史 + 附件下载路径清楚 | 历史范围默认值、附件缺失策略、媒体存储结构、导出体积限制 | 补采集规格后可做 |
| 等待处理（平台） | 需遵守 FloodWait 等 | 等待 / 权限拒绝 / 授权失效 / 冻结 的统一错误码与 UI | 与任务状态机一并定义 |
| 更新支持（平台） | 许可证期内更新的产品意图清楚 | 更新通道、强制/可选、离线可用性 | 产品与运维规格 |


### 2.1 自研候选功能（待评审，不自动纳入当前范围）

以下候选来自 `Telegram-Solutions-Feature-List.md` v1.1 对 FeitApp、TeleSender 公开页面的对照。**P1 表示优先进入 MVP 规格评审，P2 表示后续候选；两者均不代表已批准排期或开发。**

| 编号 | 候选功能 | 优先级 | 当前闭环状态 | 进入开发前需明确 |
|---|---|---|---|---|
| C01 | 活动（Campaign）管理 | P1 | 候选，未闭环 | 与 F04/任务队列边界；活动状态、暂停恢复、取消、复制、定时及中断恢复规则；重复执行的幂等边界 |
| C02 | 消息模板、个性化字段、预览与附件 | P1 | 候选，未闭环 | 变量与字段映射、缺字段处理、预览确认、附件类型/大小/失败结果；接口接受不等于送达或阅读 |
| C03 | 联系人库、标签、分群与去重 | P1 | 候选，未闭环 | 联系人字段与来源、去重键、账号实体隔离、排除/不再联系名单、删除和留存策略 |
| C04 | 成员采集筛选器与筛选预设 | P2 | 候选，未闭环 | 可用筛选字段、字段可见性、筛选逻辑、预设保存；不可可靠读取的在线状态或手机号不得作为确定事实 |
| C05 | 采集结果到活动的工作流 | P2 | 候选，未闭环 | C01/C03 依赖；字段映射、去重、来源追踪、人工确认及失败回退；采集不得自动触发发送/邀请 |
| C06 | 入站消息自动回复规则 | P2 | 候选，未闭环 | 触发范围、优先级、冷却、排除条件、停止开关、人工接管及循环回复防护 |
| C07 | 群组/频道关键词发现与候选列表 | P2 | 候选，未闭环 | 搜索来源、覆盖范围、匹配依据、可访问性；与 F06 加入动作分离，用户确认后才执行 |

**平台候选：** 活动级与收件人级结果追踪（P1，候选、未闭环）。需定义与任务状态机、实时日志、统一错误码的关联，以及“本地执行、接口接受、业务结果、未知状态”的区分；不得在无可验证数据时宣称已读、转化或最终效果。

**范围原则：** 本节候选项在完成用户故事、In/Out、验收标准、依赖与合规边界评审前，不计入 16/25 已闭环、7/25 部分闭环的原功能统计，也不进入 MVP 承诺。

## 3. 未闭环需求（明确不做）

下列项 **不进入设计、开发、验收与对外卖点**。竞品有展示亦不跟进。若未来要做，须重新立项并先完成规格闭环。

| 编号 / 项 | 功能 | 不做原因 |
|---|---|---|
| F05 | PostBot 代码发送 | 第三方机器人协议与「双代码」含义未公开，无法定义验收 |
| F17 | 机器人限制处理 | 业务语义不清；易被误解为解除服务器限制 |
| — | AI 情报分析 / CRM / 转化统计 | 公开资料不足以确认，无明确指标与数据来源 |
| — | 外部 API / CLI / Webhook | 公开资料不足以确认，无明确鉴权与范围 |

**范围约束：**

- UI、菜单、帮助文档、演示脚本中 **不得出现** 上述能力入口或承诺。
- 排期与工时估算 **不得预留** 上述项的开发缓冲（除非另行立项）。

### 3.1 产品层规格缺口（仍需补，不是「不做的功能」）

以下是实现已闭环/部分闭环功能时必须补齐的工程规格，**不属于砍掉的业务功能**。

| 缺口项 | 说明 | 闭环产出物 |
|---|---|---|
| MVP 范围 | 在「可做」集合内切第一期 | 《MVP 功能清单》含 In / Out |
| 用户故事与成功标准 | 无角色、场景、成功指标 | 每个 MVP 模块 1～3 条用户故事 + 验收 |
| 任务状态机 | 定时、恢复、去重未定义 | 状态枚举 + 转移图 + 幂等规则 |
| 错误码表 | 仅有概念分类 | 统一错误码（FloodWait、隐私、PeerFlood、Auth 失效、代理失败等） |
| 实体隔离模型 | 已知不能跨号复用，未成文 | `account_id → (peer_id, access_hash)` 存储与校验规则 |
| 安全与密钥 | Session/代理密码本地如何保护未定 | 加密方案、钥匙串/DPAPI、备份策略 |
| 双端差异 | 竞品 Windows；自研要 Win+Mac | 双端验收矩阵（路径、代理、休眠恢复、打包签名） |
| 授权与商业 | 许可证、退款、停服后可用性未定 | 授权方案（可二期）；至少明确离线可用边界 |
| 合规与文案边界 | 宣传边界需产品化 | 对外文案禁用词与功能页免责声明 |

## 5. MVP 范围（基于「可做」集合）

**平台：** Session+JSON 导入、账号列表、代理、节奏、日志、导出、SQLite 本地库、统一错误码与任务队列（同步最小集）。

**业务（MVP）：** F01、F02、F03、F06、F07、F08、F09、F11、F12、F19、F20、F23、F25。

**二期（仍做，需补规格）：** F04、F10、F13、F18、F21、F22、F24；以及 F14/F15/F16（低优先级可穿插）。

**候选功能（待评审，不计入当前 MVP）：** C01-C03（P1）优先进入 MVP 规格评审；C04-C07（P2）作为后续版本候选；平台候选“活动级与收件人级结果追踪”（P1）同步评估。规格评审通过并明确 In/Out 后，才更新 MVP 范围。

**明确不做：** F05、F17、AI 情报分析/CRM/转化统计、外部 API/CLI/Webhook。
