## 1. 产品概览

产品定位为 Windows 本地多账号操作工具，包含 25 个业务模块，支持已有用户会话导入及集中执行任务。账号与代理需要自行提供。

竞品基础目录按六类排列：消息发送 5、群组操作 4、账号相关 9、联系人 2、消息管理 2、数据采集 3，共 25 个。首页另有“7 类操作”的概括表述，与目录分类数量不同，不额外推断第七类。本文第 2.7 节另列自研候选功能及优先级；这些候选项不计入竞品原有 25 项，也不代表已批准进入 MVP。

## 2. 完整功能清单

### 2.1 消息发送（5 项）

| 编号 | 功能 | 用途 | 可能实现方式 | 限制与待核验项 |
|---|---|---|---|---|
| F01 | 按用户名发送私信 | 对用户名名单发送内容 | 解析目标用户实体，再调用消息发送接口 | 目标存在不代表可发送；接口成功不代表阅读或转化 |
| F02 | 按手机号发送私信 | 对手机号名单发送内容 | 导入联系人或按号码解析目标，再发送 | 受号码发现隐私限制；未匹配不等于未注册 |
| F03 | 按用户 ID 发送私信 | 对已有用户标识发送内容 | 使用执行账号可访问的实体信息与缓存 | 通常仅有数字 ID 不够；跨账号实体信息不能简单复用 |
| F04 | 群组定时发布 | 在目标群安排文本或转发任务 | 加入操作、消息发送、转发与任务调度组合 | 加入和发言权限分别检查；需核验重复发布、失败记录和恢复 |
| F05 | PostBot 代码发送 | 自动化第三方机器人发布流程 | 与对应机器人交互，提交其支持的发布代码或请求 | 具体协议、机器人依赖和“双代码”含义未公开 |

### 2.2 群组操作（4 项）

| 编号 | 功能 | 用途 | 可能实现方式 | 限制与待核验项 |
|---|---|---|---|---|
| F06 | 批量加入群或频道 | 集中处理目标群和频道 | 公共目标加入接口或私有邀请链接接口 | 可能需要审批；存在账号加入上限；“无限会话”不等于无限加入 |
| F07 | 批量退出群或频道 | 清理已加入会话 | 遍历会话并执行退出 | 退出不能抹除所有消息、服务记录或服务器状态 |
| F08 | 将联系人加入群 | 邀请已保存联系人 | 获取联系人实体并调用邀请接口 | 单向保存不等于双方联系人；受目标隐私和邀请权限限制 |
| F09 | 按用户名添加成员 | 根据名单处理邀请 | 解析用户后执行邀请，后台分配任务 | 调度不能改变对方隐私；群与频道的规则不同 |

### 2.3 账号相关（9 项）

| 编号 | 功能 | 用途 | 可能实现方式 | 限制与待核验项 |
|---|---|---|---|---|
| F10 | 账号养号 | 生成预设使用活动 | 执行客户端支持的活动任务 | 未验证对可用额度、账号寿命的改善；不能承诺免限制 |
| F11 | 账号检查 | 判断会话可用性 | 检查授权、获取自身资料并记录错误 | 检查正常不代表所有操作可用，也无法准确预测剩余额度 |
| F12 | SpamBot 状态检查 | 查看官方限制反馈 | 与官方机器人对话并解析结果 | 返回的是查询时状态；需核验多语言解析与无回复处理 |
| F13 | 用户行为模拟 | 模拟阅读、在线或闲置 | 协议活动或界面自动化 | 是否真的操作界面未确认；不能据此保证被判定为真人 |
| F14 | 举报工具 | 管理举报提交流程 | 封装适用的客户端举报接口 | 提交不等于处罚；不得把提交次数解释为封禁阈值 |
| F15 | 频道所有权转移 | 将频道交给另一账号 | 调用所有权转移接口并进行 2FA 验证 | 需要所有者权限及服务器要求；新会话或密码变更可能需等待 |
| F16 | 用户名占用 | 创建频道并设置可用用户名 | 创建频道、检查和设置用户名，更新频道资料 | 不保证取得保留、已占用或需购买的名称；受公开频道额度限制 |
| F17 | 机器人限制处理 | 官网表述为处理机器人侧限制 | 公开资料不足，暂不确定 | 必须演示具体机器人、输入条件和结果；不能视为解除服务器限制 |
| F18 | Session 转 TDATA | 将已有授权换为桌面格式 | 转换授权密钥、数据中心等必要会话数据 | 依赖源格式兼容性；不能凭元数据产生账号或恢复失效授权 |

### 2.4 联系人管理（2 项）

|---|---|---|---|---|
| F19 | 添加联系人 | 导入号码或已解析的用户 | 按手机号导入或添加联系人 | 不自动获得隐藏号码、双向关系或邀请权限 |
| F20 | 删除联系人 | 清理通讯录 | 读取联系人并删除 | 不等于删除聊天或重置服务器风控历史 |

### 2.5 消息管理（2 项）

| 编号 | 功能 | 用途 | 可能实现方式 | 限制与待核验项 |
|---|---|---|---|---|
| F21 | 清理全部私聊 | 删除私聊历史 | 遍历私聊并请求删除，适用时请求双方删除 | 不同会话类型规则不同；应核验范围、部分失败与操作确认 |
| F22 | 多账号统一私信中心 | 集中接收消息并由原账号回复 | 消息监听、内部群汇总、数据库映射与回复路由 | 核验串号、重复发送、附件、回复引用和断线恢复 |

### 2.6 数据采集（3 项）

| 编号 | 功能 | 用途 | 可能实现方式 | 限制与待核验项 |
|---|---|---|---|---|
| F23 | 成员采集 | 导出可访问用户资料 | 获取可见成员，或从消息整理发言者 | 成员名单和发言者集合必须区分；不保证取得隐藏名单或全部订阅者 |

## 4. 关键实现说明

### 4.1 用户会话与普通机器人

通讯录导入、聊天历史读取和直接邀请等功能需要用户客户端能力。具体使用 Telethon、GramJS 或 TDLib 尚未确认，不能仅凭界面判定技术栈。

### 4.2 用户 ID 和实体信息

常规操作通常需要用户 ID 与 access hash 等信息。实体缓存具有执行账号上下文，不能将某账号取得的信息直接当作其他账号的通用凭据。

### 4.3 采集数据来源

应明确标注每条用户数据来自成员列表、群消息或频道讨论区。评论者或发言者不等于全部成员；隐私字段为空应保留为空，不应当作真实资料补全。

### 4.4 统一私信路由

核心映射为：内部群消息 → 原接收账号 → 原用户 → 原消息。附件、回复引用、编辑删除同步与重复消息处理是需要核验的工程细节，官网简介不足以证明全部支持。

### 4.5 会话格式转换

转换只改变已有登录数据的存储形式，不改变服务器端账号状态。Session 与 TDATA 中的有效授权具有账号访问能力。

## 5. 宣传边界与未确认事项

| 表述或问题 | 应采用的判断 |
|---|---|
| 无限账号 | 仅表示许可证不限制会话数量，实际运行受资源和服务约束 |
| 任意群或频道采集 | 以账号权限和接口返回为准，不能保证完整性 |
| 养号或拟人化效果 | 缺少独立测试，不能作为免限制承诺 |
| 手机号未匹配 | 可能受隐私、限制或错误影响，不能直接判断未注册 |
| 自动等待 | 遵守等待要求，不是取消限制 |
| 举报已提交 | 不代表平台决定处罚 |
| 本地存储 | 厂商声明，尚未进行程序与网络行为验证 |
| 定时与循环任务 | 中断恢复、去重和错过时间后的策略未确认 |
| 机器人限制处理 | 业务含义及效果未明确 |
| 外部 API、CLI、Webhook | 已查看公开资料不足以确认 |
| AI 情报分析、CRM、转化统计 | 已查看资料不足以确认完整支持 |
